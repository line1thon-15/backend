# ADR-0001: 단일 Python 백엔드 + 같은 프로세스의 AI 포트 모듈

> 상태: 폐기(→ ADR-0011로 대체, 2026-11-06 — 팀 GitHub에 ai 저장소가 별도로 있음을 확인. 승인 전 제안 상태에서 폐기). 승인된 ADR은 수정하지 않는다 — 뒤집으려면 새 ADR로 대체.
> 날짜: 2026-11-06

## 맥락

- 백엔드·AI 모두 Python으로 확정됐다(PRD OQ 7 원문: AI "ai 파트가 파이썬 사용한다는데", 백엔드 "그리고 백엔드는 파이썬 형태로 진행하기로 했어"). 단일/분리 구성과 백엔드–AI API 규격은 architect가 정한다(PRD OQ 7).
- N-10: "교체에 대비해 백엔드의 AI 호출부를 별도 모듈로 분리한다. Gemini를 다른 제공사로 바꿀 때 AI 호출 모듈 밖의 코드 변경이 없어야 한다."
- 팀은 백엔드 2명, AI 1명(PRD Tasks 열 정의 원문 "디자인1, 프론트엔드 2, 백엔드 2, ai 1명"), 일정은 2026-11-12 목표·최대 11-14(N-08).
- Docker 없음(실행환경 확인).

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 단일 배포(모듈러 모놀리스) — `backend/app/ai/` 패키지가 `PracticeAI` 포트(Python Protocol + Pydantic DTO)를 제공, 제공사 SDK는 `ai/providers/`에만 | 배포·환경 변수·로그가 1벌. 네트워크 홉·서비스 간 인증 없음. 같은 pytest로 AI 모듈도 테스트(T-01 하네스 1개). N-10을 import 경계 테스트로 자동 검사 가능 | AI 파트가 백엔드 저장소 구조·Python 버전을 따라야 함. AI 모듈이 무거운 라이브러리를 쓰면 백엔드 배포가 무거워짐(1차는 SDK 1개뿐) |
| B. 백엔드·AI 분리 HTTP 서비스(각자 FastAPI) | 파트별 독립 배포·언어 버전. 책임 경계가 네트워크로 강제됨 | PaaS 서비스 2개·배포 설정 2벌·서비스 간 인증·타임아웃 처리 추가. 로컬 실행·E2E에 프로세스 3개. 일주일 일정에서 운영 부담이 이득보다 큼 |
| C. 프론트엔드가 Gemini를 직접 호출 | 백엔드 작업 감소 | API 키가 브라우저에 노출(시크릿 관리 위반), 안전 필터·검수(F-11 ②·F-42)를 서버에서 강제할 수 없음 — 탈락 |

## 결정

A를 선택한다. 결정적 이유: N-10이 요구하는 것은 "AI 호출부의 모듈 분리와 교체 시 모듈 밖 무변경"이지 프로세스 분리가 아니며, A는 이를 배포 1개로 충족하고 import 경계 테스트로 검증할 수 있다.

계약은 `backend/app/ai/ports.py`(Architecture.md "AI 모듈 경계" 표)다. 이 파일 변경은 백엔드·AI 담당이 함께 합의한다.

## 결과 (트레이드오프 포함)

- 얻는 것: 배포·운영 1벌, 단일 테스트 러너, 제공사 교체 = `providers/` 구현 추가 + `AI_PROVIDER` 값 변경.
- 감수하는 것: AI 파트의 독립 배포 불가. 나중에 분리가 필요하면 `PracticeAI` 포트의 HTTP 클라이언트 구현을 추가하는 새 ADR로 전환한다(호출하는 services 코드는 포트만 알므로 바뀌지 않음).
- 강제 장치: `tests/unit/test_import_boundaries.py` — `app.ai`가 `app.services`·`app.db`·`app.repositories`·`app.api`를 import하지 않고, 제공사 SDK import가 `app/ai/providers/gemini.py` 한 파일뿐임을 검사.
