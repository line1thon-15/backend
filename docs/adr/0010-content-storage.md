# ADR-0010: 콘텐츠 — 저장소 JSON 파일을 읽기 전용으로 적재

> 상태: 제안 (docs/Architecture.md 초안과 함께 사용자 승인 대기). 승인된 ADR은 수정하지 않는다 — 뒤집으려면 새 ADR로 대체.
> 날짜: 2026-11-06
> 2026-11-06 갱신(승인 전 제안 상태라 같은 ADR에서 범위만 고침): 저장 위치가 backend 저장소 루트 기준 `app/content/data/`가 된다(구조 변경 — Architecture.md 구조 개요). AI 서비스가 별도 저장소가 되면서(ADR-0011) `fallbacks.json`(차단 시 대체 문구)·`safety_rules.json`(안전 필터 규칙)은 **ai 저장소 소유**로 옮긴다. 백엔드에 남는 것은 출제·결과 표시에 필요한 `cues.json`·`scenarios.json`·`variants.json`·`diagnosis.json`이며, 단서 설명·상황 씨앗은 `ScenarioSpec`으로 AI 서비스에 전달한다.

## 맥락

- 단서 체계·원본 시나리오·정상 상황·진단 3문항(T-03·T-04·T-29)은 콘텐츠 담당이 만든다 — 담당은 PRD OQ 3(미정).
- 콘텐츠는 1차 동안 사람이 작성·수정하고, 런타임에 사용자가 바꾸지 않는다. 관리 화면은 PRD에 없다.
- 단서 ID는 연습 기록(cue_results)·성장 지표·보호자 리포트가 참조한다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. `backend/app/content/data/*.json`, 서버 시작 시 Pydantic 스키마·참조 무결성 검증 후 메모리에 읽기 전용 | 변경이 Git 리뷰로 추적됨, 테스트가 같은 파일을 씀, DB 마이그레이션 불필요, 잘못된 콘텐츠는 서버 시작 실패로 즉시 드러남 | 콘텐츠 수정마다 재배포 필요. 비개발자 담당은 JSON 편집 필요 |
| B. DB 테이블 + 시드 마이그레이션 | 런타임 수정 가능 | 관리 화면 없이는 이득 없음, 수정마다 마이그레이션 |
| C. 외부 시트(스프레드시트)에서 런타임 로드 | 비개발자 편집 쉬움 | 외부 의존·인증·검증 부재, 시연 중 장애 지점 증가 |

## 결정

A를 선택한다. 결정적 이유: 1차 범위에서 콘텐츠는 배포 단위로 바뀌는 정적 자산이며, 시작 시 검증으로 잘못된 단서 참조를 시연 전에 잡을 수 있다.

파일 규격은 Architecture.md "콘텐츠 파일 규격" 표. 기록 테이블은 단서를 `cue_id` 문자열로 참조한다(FK 없음) — 단서 ID는 한 번 쓰면 바꾸지 않는다(삭제·이름 변경 대신 새 ID).

## 결과 (트레이드오프 포함)

- 얻는 것: 콘텐츠·코드 동시 리뷰, 테스트 재현성.
- 감수하는 것: 비개발자 편집 편의. 콘텐츠 담당이 정해지면(OQ 3) 스프레드시트 → JSON 변환 스크립트가 필요한지 그때 판단.
