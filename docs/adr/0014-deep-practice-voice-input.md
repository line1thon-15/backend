# ADR-0014: 심화 연습 말로 답하기 — 브라우저 음성 인식으로 글자 변환, 서버는 글만 받음

> 상태: 제안 (docs/Architecture.md 초안과 함께 사용자 승인 대기). 승인된 ADR은 수정하지 않는다 — 뒤집으려면 새 ADR로 대체.
> 날짜: 2026-11-07

## 맥락

- PRD F-48 ③(2026-11-07 신규, 사용자 확인 대상, 인용): "Given 말로 답하기(Y5-3) When 아이가 말함 Then 기본안은 브라우저에서 글자로 바꾸고 음성 데이터는 우리 서버로 보내지 않으며, 바뀐 글로 ②와 같이 처리한다. 브라우저 지원 범위와 브라우저 음성 인식의 외부 전송 여부는 미확인(추정) — Open Question 53. 지원하지 않는 브라우저면 글로 답하기로 안내한다."
- 근거 사용자 원문: "심화 연습은 기획서 확인하고, 없어도 일단 추가하는 방향으로".
- 아이 목소리는 미성년자 개인정보다(N-05, PRD R-8). 1차 일정은 개발 완료 2026-11-11(팀 타임라인, 인용).
- 백엔드 공개 API는 쿠키 세션 + JSON(ADR-0013), AI 서비스는 상태 없는 JSON 서비스(ADR-0011).

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 브라우저 음성 인식(프론트)으로 글자로 바꾸고, 공개 API는 글로 답하기와 같은 `{answer_text}`만 받음 | 우리 서버·AI 서비스·로그에 음성이 없음. 백엔드·AI 작업 추가 없음(글로 답하기와 같은 경로). 업로드·오디오 형식 처리 없음 | 브라우저마다 지원 여부·정확도가 다름(추정). 일부 브라우저는 음성을 브라우저 제조사 서버로 보내 인식할 수 있음(추정 — 미확인, PRD OQ 53) |
| B. 음성 파일을 백엔드로 업로드 → 서버 또는 AI 서비스에서 STT 제공사 호출 | 브라우저 차이 없음 | 아이 음성이 우리 서버와 STT 제공사로 감, 제공사 미성년자 정책 확인(N-09) 필요, multipart·저장 금지·크기 제한 구현 추가 — 일정에 맞지 않음 |
| C. 말로 답하기를 1차에서 빼고 글로 답하기만 | 위험·작업 최소 | PRD F-48 ③·피그마 "Y7-2 심화 연습 (말로 답하기)"과 어긋남 — 범위 축소는 사용자 결정 사항 |

## 결정

A를 선택한다. 결정적 이유: PRD F-48 ③의 기본안과 같고, 아이 음성이 우리 시스템 어디에도 들어오지 않는 유일한 대안이다.

세부: 말로 답하기와 글로 답하기는 같은 엔드포인트(Architecture.md A21)와 같은 요청 DTO를 쓴다 — 요청에 음성·입력 방식 필드를 두지 않는다. 미지원·마이크 권한 거부·인식 실패면 글로 답하기(Y5-2)로 안내한다. 구현은 frontend 저장소(프론트 B, T-81)이며 백엔드 설계에는 추가 작업이 없다.

## 결과 (트레이드오프 포함)

- 얻는 것: 서버 쪽 음성 처리 0, 개인정보 노출면 축소, 백엔드·AI 일정 영향 없음.
- 감수하는 것: 브라우저 제조사 서버로의 음성 전송 가능성(추정)과 지원 범위 차이(Architecture.md 설계 리스크 D-9). T-81 착수 전 대상 브라우저 확인 결과로 외부 전송이 확인되면, 말로 답하기를 끌지(C로 전환) 사용자 결정을 받아 새 ADR로 기록한다.

## 덧붙임 (2026-11-07 — PRD OQ 55 해소·OQ 59 판단, 이 ADR이 "제안" 상태라 덧붙임)

- 근거: PRD OQ 55에 대한 사용자 답변 원문 "AI 피드백만 2차로" → 심화 연습 AI 피드백(T-78)과 공개 API A21은 2차(T-82). PRD OQ 59 architect 기본안(사용자 확인 대상, DECISIONS #72): 1차에는 아이 답변을 서버로 보내지 않는다.
- 결정 A(브라우저 음성 인식, 음성은 우리 시스템에 들어오지 않음)는 그대로다. 바뀌는 것은 "세부"의 전달 경로뿐이다: **1차**에는 바뀐 글이 A21로 가지 않고 글로 답하기(Y5-2)와 같은 프론트 메모리 상태로 넘어가 Y5-4 화면 이동에 쓰인다. **2차(T-82)**에 A21이 생기면 원래 세부("같은 엔드포인트·같은 요청 DTO, 음성·입력 방식 필드 없음")가 적용된다.
- 감수하는 것은 바뀌지 않는다: 브라우저 제조사 서버로의 음성 전송 가능성(추정 — PRD OQ 53, D-9)은 우리 서버로 글을 보내지 않아도 남는다. 1차에서 아이 음성·글이 우리 쪽 밖으로 나갈 수 있는 경로는 이것 하나다.

## 덧붙임 (2026-11-08 — PRD OQ 59 ① 사용자 확정, 이 ADR이 "제안" 상태라 덧붙임)

- 위 덧붙임(2026-11-07)의 "PRD OQ 59 architect 기본안(사용자 확인 대상, DECISIONS #72)"은 사용자가 확정했다. 메인 세션 질문 원문 "1차에 아이 답변을 서버로 보내지 않는 기본안으로 갈까요?"(PRD OQ 59 ①), 사용자 답변 원문 "기본안대로"(2026-11-07) — DECISIONS #76.
- 이 ADR의 결정 A와 위 덧붙임의 1차·2차 전달 경로는 바뀌지 않는다. 이 ADR의 상태("제안")는 Architecture 승인과 함께 사용자가 정한다.
