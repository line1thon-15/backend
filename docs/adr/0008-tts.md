# ADR-0008: TTS — 브라우저 내장 Web Speech API

> 상태: 제안 (docs/Architecture.md 초안과 함께 사용자 승인 대기). 승인된 ADR은 수정하지 않는다 — 뒤집으려면 새 ADR로 대체.
> 날짜: 2026-11-06
> 2026-11-06 갱신: TTS 구현 위치는 frontend 저장소(프론트 담당)다. 이 ADR은 N-09 제공사 기록과 백엔드 무관성(TTS용 API 없음)을 정하는 설계 결정이며, 프론트에는 권고로 전달한다(Architecture.md "팀원 요청 사항").

## 맥락

- F-27 음성 읽어주기: Y4 대사·Y5 카드 읽기, 설정에서 끄면 버튼 숨김(1차, P1 — T-44).
- PRD OQ 2 잔여 "TTS 제공사"(보류 — 구현 중 결정), N-09 "그 밖의 제공사(TTS 등…)는 미성년자 이용 조건 확인 기록을 설계 문서에 남긴 뒤 사용한다".
- 읽는 문장은 연습 대사·단서 카드뿐(예시 콘텐츠, 개인정보 없음).

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 브라우저 Web Speech API(`speechSynthesis`) | 키·계약·서버 비용 없음, 우리 서비스가 계약하는 외부 제공사 없음, 지연 없음 | 브라우저·OS마다 한국어 음성 유무·품질이 다름. 일부 음성은 네트워크 음성일 수 있음(추정) |
| B. 클라우드 TTS(예: Google Cloud TTS 등)를 백엔드에서 호출 | 음성 품질 일정 | 키·과금·미성년자 이용 조건 확인(N-09) 필요, 오디오 전송·캐시 구현 추가 |
| C. 미리 녹음·생성한 오디오 파일 | 품질 일정, 외부 호출 없음 | AI가 실시간으로 만드는 대사(F-11)에는 쓸 수 없음 |

## 결정

A를 선택한다. 결정적 이유: AI가 실시간 생성하는 대사를 추가 계약·키 없이 읽을 수 있는 유일한 대안이다.

세부: `TtsButton`은 `tts_enabled`이고 `window.speechSynthesis`가 있을 때만 보인다. `lang`이 `ko`로 시작하는 음성 중 `localService === true`를 우선 선택한다. 한국어 음성이 없으면 버튼을 숨기지 않고 쉬운 말로 "이 기기에서는 읽어주기를 쓸 수 없어요" 류 안내를 보인다(문구는 콘텐츠).

## 결과 (트레이드오프 포함)

- 얻는 것: N-09 추가 제공사 없음, 구현 단순.
- 감수하는 것: 기기별 품질 차이. 네트워크 음성 여부는 T-44에서 대상 브라우저별 `localService` 값을 기록해 확인(Architecture.md "AI 제공사 정책 기록" 표). 품질이 시연에 부족하면 B로 가는 새 ADR.
