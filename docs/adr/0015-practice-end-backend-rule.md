# ADR-0015: 연습 종료는 백엔드 규칙만 — `is_terminal` 삭제, A17은 `PracticeSessionView`로 종료를 알림

> 상태: 제안 (사용자 확인 대상 — Architecture.md 머리글 상태 "승인"은 그대로, 이 결정은 바뀐 부분만 확인). 승인된 ADR은 수정하지 않는다 — 뒤집으려면 새 ADR로 대체.
> 날짜: 2026-11-08

## 검토한 대안

결정 1 — 내부 `TurnResult.is_terminal` 처리:

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 필드 삭제 + 백엔드는 응답의 규격 밖 필드를 무시(전환 허용) | 계약이 결정(AI는 종료를 판정하지 않음)과 일치 — 쓰이지 않는 필수 필드를 AI가 계속 채우는 일이 없음. 누군가 다시 이 값으로 종료를 정하는 회귀 경로가 사라짐(F-11 ⑥). 계약 고정 전·AI 하네스 착수 전이라 AI 쪽 비용이 가장 작음. 무시 규칙 덕에 AI가 늦게 고쳐도 503이 나지 않음 | T-01 완료 코드 수정 필요(재작업 태스크 — 아래 결과). 계약 고정 후 규칙("필드 삭제는 양 담당 합의")상 AI 담당 알림 필요(AI-5) |
| B. 필드 유지(필수), 백엔드는 읽지 않음 | T-01 코드 무변경 | AI가 의미 없는 값을 계속 만들어야 함. 규격이 "AI가 종료를 알린다"로 읽혀 결정과 어긋남. 이후 구현자가 값을 다시 쓰는 회귀 위험 — F-11 ⑥을 규격이 아니라 주의로만 지킴 |
| C. 선택 필드(`bool \| None = None`)로 바꾸고 "사용 금지" 표시 | AI가 보내도 안 보내도 됨 | B와 같은 회귀 위험이 남고, 쓰지 않을 필드를 규격에 남김. T-01 코드도 결국 수정 필요 |

결정 2 — 종료하는 답(A17)의 공개 응답과 Y4 종료 신호:

| 대안 | 장점 | 단점 |
|---|---|---|
| A. A17도 `PracticeSessionView`를 반환 — `status: "in_progress"` + 다음 턴, 또는 `status: "ended"` + `turn: null`. `TurnView.is_terminal` 삭제 | A15·A16·A17 응답이 한 형태 — 프론트 렌더러 1개. 새로고침(A16)으로 종료 세션에 들어온 경우도 같은 규칙(`ended` → Y5). 보이는 턴은 항상 답할 턴이라 `TurnView`에 종료 필드가 필요 없음 | A17 응답 형태 변경(공개 API) — 프론트 알림 필요(F-9). 계약 미고정·T-18 대기라 비용 작음 |
| B. A17은 `TurnView` 유지, 종료면 `is_terminal: true`이고 `ai_line`·`choices` 등을 null/빈 값 허용 | 응답 이름 유지 | `TurnView` 필드 대부분이 조건부 null이 되어 화면이 "빈 턴"을 처리해야 함. A16과 종료 표현이 달라짐 |
| C. 새 DTO `{status, turn \| null}` | 의미가 명확 | `PracticeSessionView`와 사실상 중복 — DTO 하나 더 |

## 결정

- 결정 1: **A** — 내부 `TurnResult.is_terminal`을 삭제하고, 백엔드는 응답의 규격 밖 필드(전환 중의 `is_terminal` 포함)를 무시한다. 결정적 이유: 사용자 결정 "AI의 종료 신호는 쓰지 않습니다"를 규격 자체로 강제하는 유일한 대안이다.
- 결정 2: **A** — A17은 `PracticeSessionView`를 반환하고 종료는 `status: "ended"` + `turn: null`로 알린다. 공개 `TurnView.is_terminal`은 삭제한다. 결정적 이유: "바로 결과 화면"이면 종료하는 답 뒤에 보일 턴이 없으므로, 턴이 없는 상태를 이미 표현할 수 있는 세션 응답이 맞다.
- 종료 규칙(DECISIONS #80): 백엔드 domain 순수 함수, 입력 = `is_normal`·고른 선택지 `judgment`·아이 답 수(답한 턴 `turn_index + 1`, 첫 대사 = 0). 위험 상황: `suspicious` → 종료, 답 수 ≥ `MAX_CHILD_ANSWERS`(=4) → 종료, 그 외 계속. 정상 상황: PRD OQ 61 — 규칙 없음(예외).

## 결과 (트레이드오프 포함)

- 얻는 것: 종료 시점이 AI 출력과 무관하게 결정적 — Fake 없이도 domain 단위 테스트로 F-11 ④⑤⑥ 검증. 종료하는 답에서 `next_turn` 호출 1회 절약(사용자 답 설명 "AI 호출이 한 번 줄고").
- 감수하는 것:
  - **T-01 완료 코드 영향**(코드는 고치지 않음 — AGENTS.md "이미 완료된 태스크의 구현을 바꿔야 함" 행에 따라 planner가 재작업 T-xx 생성): `app/ai_client/ports.py:55`(`is_terminal: bool` 삭제), `app/ai_client/fake.py:32`(`is_terminal=False` 인자 삭제), `tests/unit/test_fake_practice_ai.py:55`(`assert result.turn.is_terminal is False` — 필드 삭제 후 실패하므로 삭제 또는 "`is_terminal` 키 없음" 단언으로 교체), `:125`(테스트 입력 dict의 `"is_terminal": False` — 삭제 권고). 추정: pydantic v2 기본 `extra="ignore"`라 `fake.py:32`와 `:125`는 필드 삭제 후에도 오류 없이 무시될 수 있으나 남기면 규격과 어긋난다 — 확인 방법: 재작업 태스크에서 pytest 실행.
  - 공개 A17 응답 형태 변경 → 프론트 알림(Architecture 팀원 요청 F-9). 내부 규격 변경 → AI 담당 알림(AI-5).
  - 종료가 AI가 붙인 `judgment` 태그에 의존 — 태그 오류가 종료 시점을 바꾼다(Architecture D-11). 백엔드는 태그 구성 제약(DECISIONS #83, 사용자 확인 대상)만 검증.
  - 종료하는 답의 A17도 `judge`(AI)를 호출하므로 그 요청이 실패할 수 있다 — 한 트랜잭션으로 묶어 실패 시 아무것도 저장하지 않고 같은 선택지로 다시 시도.
  - "대신 상대 반응 없이 끝나 갑작스럽게 느껴질 수 있습니다"(사용자 선택지 설명 원문)는 화면 문구 몫 — 설계 변경 없음.
