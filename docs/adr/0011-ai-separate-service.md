# ADR-0011: 백엔드–AI 구성 — ai 저장소를 별도 HTTP 서비스로, 백엔드는 포트 + HTTP 어댑터

> 상태: 제안 (docs/Architecture.md 초안과 함께 사용자 승인 대기). ADR-0001을 대체한다. 승인된 ADR은 수정하지 않는다 — 뒤집으려면 새 ADR로 대체.
> 날짜: 2026-11-06

## 맥락

- ADR-0001(제안)은 AI 모듈을 백엔드 저장소 안 같은 프로세스 패키지로 두었다. 그 뒤 메인 세션이 2026-11-06 gh CLI로 확인한 팀 GitHub 조직 line1thon-15의 실제 구성(인용): 저장소 `ai`("AI 레포지토리 (LLM 생활 판단 연습·피드백)", 비어 있음), `backend`("백엔드 레포지토리", 비어 있음)가 따로 있고, 팀 GitHub docs 저장소의 README 원문 "| `ai` | LLM 기반 생활 판단 연습·피드백 로직 |", "AI 구현 상세 | ai/docs". AI 담당은 1명(팀 구성 원문 "디자인1, 프론트엔드 2, 백엔드 2, ai 1명").
- 사용자 담당은 backend 저장소(사용자 원문 "내가 접근할 곳은 backend 부분 쪽이야"). 에이전트 파이프라인은 사용자 범위에만 쓴다(PRD Tasks 열 정의).
- N-10: "Gemini를 다른 제공사로 바꿀 때 AI 호출 모듈 밖의 코드 변경이 없어야 한다."
- 백엔드·AI 모두 Python(PRD OQ 7).

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. ai 저장소 = 독립 HTTP 서비스(내부 API `/internal/v1`). 백엔드는 `PracticeAI` 포트를 두고 `HttpPracticeAI`(운영)·`FakePracticeAI`(테스트·E2E) 두 구현을 가진다 | 팀이 이미 나눈 저장소·담당 경계와 일치. AI 담당이 백엔드 없이 독립 개발·테스트·배포. 백엔드 코드에 제공사 SDK·키가 아예 없어 N-10이 가장 강하게 성립(제공사 교체는 ai 저장소 안의 일). Gemini 키가 AI 서비스 환경 변수에만 존재 | PaaS 서비스 1개 추가(배포·환경 변수·비용 [A-2]), 서비스 간 인증 토큰·시간 초과 처리, 네트워크 지연, 두 저장소 간 계약 어긋남 위험 |
| B. ai 저장소를 Python 패키지로 만들어 백엔드가 `pip install git+https://github.com/line1thon-15/ai@<태그>`로 설치(같은 프로세스) | 배포 1개, 네트워크 홉 없음. ADR-0001의 포트 구조 그대로 | 저장소가 비공개면 PaaS 빌드에 접근 토큰 필요(공개 여부 미확인). AI 변경마다 백엔드 의존성 갱신·재배포 → AI 담당이 독립 배포 불가. AI 패키지의 의존성이 백엔드와 충돌 가능. 패키징 작업이 AI 담당에게 추가 |
| C. ADR-0001 유지(AI 코드를 backend 저장소에) | 가장 단순 | 팀이 만든 ai 저장소·담당 경계와 어긋남 — 팀 합의 없이 강요 불가 |
| D. 프론트가 AI 서비스를 직접 호출 | 백엔드 경유 없음 | 키·안전 필터 우회 위험, 연습 기록 저장·인가가 백엔드를 거치지 않음 — 탈락 |

## 결정

A를 선택한다. 결정적 이유: 팀이 이미 정한 저장소·담당 분리와 일치하면서, 백엔드에서 제공사 의존을 완전히 없애 N-10을 가장 단순하게 보장한다.

세부(규격은 Architecture.md "백엔드–AI 내부 API"):
- AI 서비스는 상태가 없다(DB 없음). 백엔드가 매 호출에 `ScenarioSpec`과 대화 이력을 보낸다.
- 인증: 헤더 `X-Internal-Token`(양쪽 환경 변수 `AI_SERVICE_TOKEN` — 시크릿).
- 안전 필터·출제 전 검수·찾음/놓침 판정·피드백 문구는 AI 서비스 책임(Tasks T-12·T-14·T-63 담당 AI). 백엔드는 응답을 스키마로 검증하고(선택지 `cue_ids ⊆ 목표 단서`, 선택지 2~4개) 위반·비2xx·시간 초과를 `AI_UNAVAILABLE`로 바꾼다.
- 백엔드 테스트·E2E는 `AI_CLIENT=fake`(백엔드 안의 `FakePracticeAI`)로 AI 서비스 없이 돈다.

B는 두 번째 PaaS 서비스를 쓸 수 없을 때(비용·계정 — [A-2])의 대체안으로 남긴다. 전환하면 새 ADR.

## 결과 (트레이드오프 포함)

- 얻는 것: 파트별 독립 진행, 백엔드에 Gemini 키·SDK 없음, 약관 문제(PRD R-1)로 제공사를 바꿔도 백엔드 무변경.
- 감수하는 것: 배포 단위 3개(프론트·백엔드·AI), 호출당 네트워크 지연, 계약 어긋남. 대응: 내부 API 규격을 팀 docs 저장소에 정본으로 게시하고, 백엔드 `tests/contracts/ai/`의 요청·응답 샘플 JSON을 같은 곳에 공유해 AI 저장소도 같은 샘플로 테스트하도록 요청한다(AI 담당 합의 필요 — [A-8]).

## AI 담당 합의 기록 (2026-11-07 추가 — 이 ADR은 아직 "제안" 상태라 결정 내용은 바꾸지 않고 기록만 덧붙인다)

- 메인 세션 질문 원문(인용): "지금 설계는 ai 레포에 서버를 따로 띄우고, 백엔드가 "첫 대사/판정/요약 문장 만들어 줘" 하고 API로 요청하는 구조예요. AI 서버를 따로 만드는 게 괜찮으신지, 아니면 AI 코드를 백엔드 안에 함수로 넣는 게 편하신지 알려 주세요"
- AI 담당 답변 원문(사용자 전달, 인용): "1. 동의합니다. AI 레포에서 별도 HTTP 서버(8081)를 운영하는 방식으로 진행하겠습니다."
- 결과: 대안 A에 AI 담당이 동의 — [A-8] 해소, 대안 B(pip 패키지)로 전환하지 않는다. 포트 8081은 Architecture.md "시크릿과 환경 변수"·"팀 공유 규격"의 로컬 포트와 같다.
- 남은 것: 엔드포인트별 필드 규격·`X-Internal-Token`·계약 샘플 JSON 공유는 답변에 언급이 없어 미확인([A-16]). 이 ADR의 상태를 "승인"으로 바꾸는 것은 사용자만 한다 — AI 담당 합의는 사용자 승인이 아니다.
