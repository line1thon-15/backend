# ADR-0019: `variant` fallback이 직전 변형과 같을 때 — 503 대신 다른 변형 1회 재요청 후 원본 진행

> 상태: 제안 — 방향은 2026-11-14 사용자 결정(아래 맥락, DECISIONS #133). 상태 "승인" 전환은 사용자. 승인된 ADR은 수정하지 않는다 — 뒤집으려면 새 ADR로 대체.
> 날짜: 2026-11-14
> 대체 범위: DECISIONS #102(→ #115 확정)의 "`source = fallback`이면 직전 세션과 `platform`·`tone` 차이 검사 — 차이가 없으면 503" 부분, [ADR-0017](0017-ai-contract-alignment.md) "결과"의 "`variant`의 fallback만 F-12 검사(변형 차이)에 걸려 503이 될 수 있다" 부분. 두 문서의 나머지(VA1~VA3, `model` 응답의 VA4, 변형 값 선택 규칙)는 그대로다. ADR-0017 본문은 수정하지 않았다.

## 맥락

- 기존 규칙(Architecture "1차 내부 API v1" `variant` 행 VA4, 구현 `app/services/practice_validation.py:67-68`): 같은 아이의 같은 `scenario_id` 직전 세션(다시 도전이면 `retry_of`)과 `platform` 또는 `tone`이 1개 이상 달라야 하고, `fallback`(원본 시나리오)이 이를 못 지키면 503.
- 팀원 리뷰 원문(PR #25, 사용자 전달 — 인용): "AI 서버에서 모델 생성에 실패하면 `source="fallback"`으로 원본 시나리오를 반환합니다. 이 상태에서 같은 시나리오를 다시 도전하면 이전과 동일한 플랫폼·말투가 반환되어 백엔드의 `VA4` 검증에 걸리고, `503 AI_UNAVAILABLE`이 발생할 수 있습니다."
- 메인 세션 재현(인용 — architect 미재실행): `.artifacts/verification/T-94/main-20261114-live-ai-retry/` (AI 서버 ai dev e82ea66, `AI_PROVIDER=fake` — fake 제공자는 고정 문장을 돌려줘 변형이 항상 fallback → 다시 도전 A15 503).
- 사용자 결정(2026-11-14) 질문 원문: "다시 도전 503 문제(재현됨): AI가 변형 생성에 실패해 원본 시나리오(fallback)를 돌려주면, 다시 도전이 직전과 같은 플랫폼·말투가 돼 백엔드가 거부(VA4)하고 503이 나요. Gemini 실패·한도 초과 때도 같은 일이 생겨요. 어떻게 고칠까요?" / 답 원문: "백엔드가 다른 변형 요청 (추천)" / 선택지 설명 원문: "fallback이 직전과 같으면 백엔드가 다른 플랫폼·말투로 한 번 더 요청하고, 그래도 같으면 원본으로 진행(같은 모습 허용). 백엔드만 고쳐서 바로 끝낼 수 있어요. 단 F-12 '다른 모습'이 깨질 수 있어요."
- PRD F-12 [2026-11-14 예외] 각주(docs/PRD.md:77, planner 반영 — 인용).

## 검토한 대안

사용자에게 보인 다른 선택지의 원문은 architect에 전달되지 않았다(미확인). 아래 A·C·D는 architect가 비교를 위해 적은 것이다.

| 대안 | 장점 | 단점 |
|---|---|---|
| A. 기존 유지 — fallback이 직전과 같으면 503 | F-12 "다른 모습"을 항상 지킴 | Gemini 실패·한도 초과 동안 같은 시나리오 재출제·다시 도전이 계속 503(재현됨). fake 제공자로는 다시 도전이 항상 실패 |
| B. 다른 조합으로 1회 재요청, 그래도 fallback이 같으면 원본으로 진행 (**사용자 선택**) | 백엔드만 수정. 일시적 생성 실패는 재요청으로 "다른 모습"을 회복할 기회가 있음. 오류 대신 연습 진행 | AI 호출이 최대 1회 늘어남(그 경우 응답 지연). 생성이 계속 실패하면 같은 모습으로 진행 — F-12 미충족 가능 |
| C. fallback이면 VA4를 적용하지 않고 바로 원본 진행 | 가장 단순, 호출 증가 없음 | 일시적 실패에도 "다른 모습"을 회복할 기회가 없음 |
| D. AI가 fallback에서도 요청한 `platform`·`tone`을 반영하도록 AI 저장소에 변경 요청 | F-12를 AI 쪽에서 보장 | 다른 저장소 변경·합의가 필요해 일정 위험. 원본 시나리오 대체의 의미(검수된 원문)가 바뀜 |

## 결정

B. 결정적 이유: 사용자 결정 "백엔드가 다른 변형 요청 (추천)".

규칙(A15 새 출제·다시 도전 공통 — VA4는 직전 세션이 있을 때만 적용되므로 직전 세션이 없으면 이 절차도 없다):

1. 첫 요청: 기존대로 domain이 직전 조합과 다른 `(platform, tone)`을 골라 `variant` 호출.
2. 첫 응답 검증: VA1·VA2는 항상, `source = model`이면 VA3·VA4(기존 그대로 — 위반 503). `source = fallback`이고 `(platform, tone)`이 직전과 다르면 그대로 채택.
3. 재요청 조건: 첫 응답이 `source = fallback`이고 `(platform, tone)`이 직전과 같을 때만. 재요청은 **1회만**(오류 재시도가 아님 — 비2xx·시간 초과·스키마 위반은 재요청하지 않고 기존대로 503).
4. 재요청 조합: 시나리오 `variation_axes` 조합 중 `(platform, tone)`이 직전 세션 조합 및 첫 응답 조합과 다른 것에서, 첫 선택과 같은 규칙(F-08 선호 플랫폼 우선, 주입 난수)으로 고른다. `context`도 같은 규칙으로 다시 고른다. 첫 요청 조합은 제외하지 않는다(다시 뽑힐 수 있음). 남은 조합이 없으면 재요청하지 않고 첫 응답(원본)으로 진행한다.
5. 재요청 응답 검증: VA1·VA2는 항상. `source = model`이면 VA3(재요청 값 기준)·VA4(직전 기준) 그대로 — 위반 503. `source = fallback`이면 VA4를 적용하지 않고 채택(직전과 같아도 진행).
6. AI 호출 실패: 첫 요청·재요청 어느 쪽이든 비2xx·연결 실패·시간 초과·응답 스키마 위반이면 `AIUnavailableError` → 503 `AI_UNAVAILABLE`, 아무것도 저장하지 않는다(기존 #85 원칙).
7. `start`는 채택한 변형으로 1회만 호출한다. 세션에는 채택한 변형을 저장한다(다음 다시 도전의 직전 조합이 된다).

## 결과 (트레이드오프 포함)

- 얻는 것: fallback이 직전과 같은 경우의 503이 사라진다(Gemini 실패·한도 초과·`AI_PROVIDER=fake` 포함). 다시 도전·같은 시나리오 재출제가 진행된다.
- 감수하는 것: 그 경우 F-12 "다른 모습"이 충족되지 않을 수 있다(PRD F-12 [2026-11-14 예외]가 허용). 해당 출제는 `variant` 호출이 2회가 되어 응답이 늦어질 수 있다. 화면(TurnView 턴 0 `substituted`)은 기존대로 false — 같은 모습 진행을 화면에 따로 알리지 않는다(PRD에 요구 없음).
- 테스트(T-95 — 구현 세션 범위, architect가 정한 최소 케이스): ① 직전 없음 → `variant` 1회 ② 첫 응답 fallback·직전과 같음 → 재요청 1회, 재요청 조합이 직전과 다름 ③ 재요청이 model(VA3 통과) → 그 변형으로 세션 생성 ④ 재요청도 fallback·같음 → 같은 모습으로 세션 생성(200), `variant` 총 2회 ⑤ 재요청 HTTP 오류 → 503, 저장 없음 ⑥ 첫 응답 model인데 VA3 위반 → 재요청 없이 503 ⑦ 첫 응답 fallback이지만 직전과 다름 → 재요청 없이 채택.
